# 13 — DEVOPS / DEPLOYMENT

## תהליך הפריסה הקיים (כפי שניתן להוכיח)
1. אין scripts, אין CI, אין IaC. ה-commit היחיד בהיסטוריה: `2bb653d "Add files via upload"` → הפריסה בפועל היא **העלאה ידנית של קובץ** (וגם השורה השבורה ב-CSS מעידה על כך — FINDING-002).
2. יעד ההגשה לא מאומת מהמאגר (OPEN-Q3): GitHub Pages / העלאה לשרת / פתיחה מקומית — כל אחד מתאים לקובץ סטטי.

## מה חסר (מדורג)
| חסר | השפעה | תעדוף |
|---|---|---|
| תהליך פריסה מתועד וחוזר | שינויים ידניים שבירים (ראיה: 002) | P2 |
| CI מינימלי (syntax/lint/deploy) | אין רשת ביטחון לפני פרסום | P2 |
| הפרדת סביבות (dev/prod RTDB) | ניסויים פוגעים בנתוני משתמשים חיים | P1 כחלק מ-002 |
| Monitoring (Firebase usage, errors) | אין נראות לתקלות | P3 |

## המלצת פריסה מינימלית (מתאימה לקובץ סטטי)
- **GitHub Pages מה-main** (כבר על GitHub) עם דף index תקין — או כל static host (Netlify/Cloudflare Pages).
- להוסיף `deploy` script פשוט + workflow שמריץ `node --check` (הוכחה כשימושית — היה מונע 002) לפני publish.
- **לפני כל פריסה:** TASK-002 חייב להיות מבוצע — פריסת הנוכחית עם rules פתוחים אינה מקובלת.
