# 15 — PERFORMANCE

## מדידות סטטיות (ללא ריצת דפדפן)
| מדד | ערך/הערכה | בסיס |
|---|---|---|
| גודל המסמך | ~52KB (1,240 שורות) HTML+CSS+JS | ✅ קטן |
| תלות רשת לרינדור ראשוני | 4 בקשות חוסמות: fonts CSS + Chart.js (~205KB) + Firebase SDK ×2 | 🟡 FINDING-022 |
| TTI הערכה | תלוי ב-CDN; ברשת איטית הסקריפטים חוסמים | 🟡 |
| גודל DOM/רינדור טבלה | לינארי במספר הזנים; רינדור מחדש מלא בכל פעולה | ✅ סביר עד מאות זנים; 🔵 מעל אלפיים יורגש |
| חיפוש | O(n) בזיכרון | ✅ |
| סטטיסטיקות | O(n) reduce | ✅ |
| localStorage כתיבה | כל saveData = serialize מלא | ✅ בהיקף נוכחי |
| Firebase payload | set() מלא של הקטלוג בכל שינוי קטן | 🟡 נגזרת של 003 |
| Polling | setInterval 2s ללא עצירה | 🔵 FINDING-020 |
| Chart destroy/rebuild | מבוצע נכון — אין איסוף גרפים | ✅ |

## מסקנות
- **בהיקף הנוכחי (רשימה אישית) הביצועים אינם בעיה.**
- שיפורים מהירים בעלי תמורה גבוהה: `defer` לשלושת הסקריפטים (022), מזעור כתיבות Firebase (נגזרת TASK-005), lazy-load של Chart.js רק בכניסה לטאב.
- **לא מומלץ** להקדיש מאמץ ל-bundling/minification לפני סגירת הפערים המהותיים (P2 ומעלה).
