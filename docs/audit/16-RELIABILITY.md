# 16 — RELIABILITY

## מאפייני אמינות נצפים
| תחום | מצב | ראיה |
|---|---|---|
| Offline-first | ✅ טוב | fallback ל-localStorage בכל נתיב Firebase |
| טיפול בשגיאות סנכרון | ✅ בסיסי | .catch על כל קריאת Firebase עם חיווי |
| טיפול בשגיאות UI | 🟡 חלקי | try/catch ביבוא/קליטת תוסף; חסר ב-saveData (021), ב-copyLink (007), ב-renderStats (006) |
| סנכרון מרובה מכשירים | ❌ לא בטוח | last-write-wins על מערך שלם (003) — סיכון אובדן נתונים שקט |
| אינטגריות נתונים | 🟡 | validation ביבוא טוב; חסר בטעינת ענן (004) |
| רסטארט/התאוששות | ✅ | כל טעינת עמוד = טעינה מחדש מהמקורות |
| גיבוי/שחזור | 🟡 ידני בלבד | ייצוא JSON; מחיקה גורפת ללא רשת-ביטחון (011) |
| Degradation נחמד | ✅ ברובו | CDN חסום פוגע מקומית (גרף) ולא בכל האפליקציה |

## Failure modes מדורגים
1. **אובדן נתונים בסנכרון** (003) — הסיכון האמיתי היחיד לנתוני המשתמש.
2. **מחיקה גורפת** (011) — בכוונת מכוון אך ללא רשת-ביטחון.
3. **קריסות נקודתיות** (006, 017, 021) — מקומיות לטאב/פעולה.

## מסקנה
האמינות הבסיסית טובה מהצפוי לקובץ-יחיד; הפער המהותי הוא סמנטיקת הסנכרון (003) — הוא גם המטרה המוצהרת של המערכת ("מסונכרן בענן"), ולכן דורג High.
